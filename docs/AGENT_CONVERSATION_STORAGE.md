# Agent 会话归档原型

会话归档默认关闭，由部署环境显式启用。数据库迁移 `0032_agent_conversation_archive` 接续 develop 已有的 `0031_referral_reward_rules`，保留邀请拉新规则及注册邀请码功能。以下保留最初权限分析，当前实现以 [管理员权限](ADMIN_PERMISSIONS.md) 为准；代码合入不代表实际服务器已启用归档。

## 2026-11-09 权限分析（历史候选方案）

普通管理员继续负责正常用户管理、查账对账、积分补发/扣回/退还及兑换码发放。建议进一步区分：

| 操作 | 普通管理员 | 超级管理员 |
| --- | --- | --- |
| 用户管理 | 管理普通用户及其会话 | 管理管理员账号、授予/撤销后台权限 |
| 积分业务 | 在授权额度内执行日常业务 | 配置累计发放额度、超额及全站批量发放 |
| 全站规则 | 查看、测试、准备草稿 | 发布全站费率、默认赠送、免费开关及重大 Agent 规则 |
| 私密数据 | 自己的会话、业务必需数据、用户主动提交的反馈 | 跨用户会话正文查询、搜索和导出 |
| 数据维护 | 标记、归档、正常反馈处理 | 批量永久删除、改变留存期限、关闭归档 |
| 审计 | 职责范围内的操作记录 | 全部管理员的敏感访问与变更审计 |

最初基线中的 `websiteAdminAccess` 允许所有 admin 授予 admin；初始管理员来自服务器 `BETTER_AUTH_ADMIN_USER_IDS`，网页不能变更该名单。后续权限分级应收紧角色授予及管理员相互管理。积分预算需跨直接发放、兑换码等入口累计，单笔上限不能替代预算。审计不应提供网页修改/删除入口。服务器 SSH、数据库、备份恢复、密钥轮换权限单独管理，网站超级管理员不自动拥有服务器权限。

2026-11-21 已按用户指令落地超级管理员分级：所有会话导出（含个人范围）、跨用户会话查询仅限服务器名单中的超级管理员。普通用户及普通管理员保留自己会话的查看和删除。角色授予、后台账号管理、全站计费汇总/月报/成本、全局 Agent 策略和 PR #780 的拉新活动开关均已收紧；日常用户及积分业务仍开放给普通管理员。未实现历史候选中的累计积分预算、批量清库或留存期限控制。

## 存储与责任

复用 PostgreSQL、Drizzle 和 AI SDK。保存会话及每次请求尝试：当前用户消息与服务端生成的 assistant 消息分别存储，保留结构化 parts 和便于分析的文本。重试保留为不同尝试；同一 attempt 重复请求拒绝再次执行。浏览器提供的旧 assistant 历史不作为服务端生成记录导入。

在现有认证、输入校验及内容过滤之后、模型调用之前写入用户消息；写入失败不调用模型。直连与网关均从经过现有边界处理的 UI 消息流提取回复，约每秒保存一次快照并在终态保存。输出归档失败通过消息中的归档状态提醒用户，保留已显示的回复。状态区分 streaming、completed、cancelled、failed、interrupted。进程崩溃可能丢失上次成功快照之后的片段；过期 streaming 记录在查询时标记 interrupted。

文本附件保存文字、文件元数据和摘要；图片/二进制仅保存元数据与摘要，不保存正文或原始 URL。不存模型隐藏推理，不收集密钥、Cookie、服务器系统提示词。工具调用/返回属于服务端 UI 消息 parts；其中用户数据也受同样的正文权限保护。原型未提供历史导入、跨设备续聊或图片恢复。

## 使用和导出

开关：`AGENT_CONVERSATION_STORAGE_ENABLED=1`；其它值均关闭。数据库先执行本分支提交的 Drizzle 迁移。不要向已有真实用户数据库运行原型测试。部署时先审核并应用迁移，再在服务进程配置中开启归档；本机的开关不影响远端。

用户入口 `/agent-archive` 仅提供自己的查看/删除；其中导出按钮仅超级管理员可见。超级管理员入口 `/admin/agent-archive` 提供全站查询和导出。后台侧栏的“会话导出”和“权限管理”入口仅超级管理员可见，前者直达该页面；后者 `/admin/permissions` 展示服务器名单并管理普通后台角色。查询和导出接口均验证当前登录用户及数据库中的有效账号；超级管理员还必须在服务器名单中且非代登录会话。服务端逐次校验，不能只隐藏按钮。支持账号、时间筛选以及 JSON/JSONL 下载；导出从当前服务器数据库发送到浏览器，由浏览器保存到当前电脑。

全量指启用归档后仍保留的全部已结束尝试，不包括仅留在浏览器 IndexedDB 的历史、仍在生成或截止时间后结束的尝试。列表/详情可以查看生成中的快照。时间筛选按尝试发送时间计算；未指定时间则导出全部已结束记录。

导出采用固定截止时间、同一个 PostgreSQL REPEATABLE READ 只读快照和游标批量读取，不静默截断为一页；导出中删除记录不会使后续页静默缺失。快照在首次读取时建立，完成或取消时释放，数据库限制空闲事务最长 60 秒。每 200 条重新检查当前账号、服务器名单与登录 Session 有效性；撤权后已发出的内容不能收回，最多尚有当前批次已授权的记录继续发送。流式导出以末尾完成记录区分完整和中断。记录操作人、范围、请求编号、数量和结果，不向审计重复复制对话正文。审计中的数量表示服务端发送数量，不证明文件已被用户完整保存。响应禁止缓存，文件不放到公共静态目录。

本地不自动删除历史；用户可删除自己的归档会话，删除账号由数据库外键级联清除。生成中的会话拒绝删除；删除与新问答开始共用会话行锁，防止并发操作误删刚写入的问题。生产保留期限尚未决定。既有浏览器最近 5 条会话历史独立保留。

## 验证与剩余工作

`npm run test:agent-conversations` 使用模拟模型和独立 PostgreSQL 数据库，覆盖结构化双方正文、附件处理、并发编号、重复请求、失败/取消/中断、所有者隔离以及跨批次完整导出。`npm run test:admin-permissions` 检查真实签名 Session 的角色边界；`npm run test:billing-monthly` 检查月界、精度和成本去重；`npm run test:super-admin:browser` 检查四种角色的页面、菜单、角色操作及 API。

这些脚本只连接 localhost，创建随机命名的 `*_test` 数据库、应用迁移，并在结束时删除测试库。可通过 `RIIC_TEST_ENV_DIR` 指定本地连接配置目录；连接值不输出。测试不创建或修改密码，不调用付费模型。异常终止可能留下临时库，应核对随机名称后再清理。

本地演示：`npm run dev:agent-conversations`，默认使用 `http://127.0.0.1:5186/agent-archive` 和 `/admin/agent-archive`，可用 `AGENT_ARCHIVE_DEMO_PORT` 改端口。演示使用临时库、合成用户和示例对话，禁用模型调用及计费入口，正常停止后清理。先运行演示，再运行 `npm run test:agent-conversations:browser`，可检查浏览器下载和移动端布局。截图、导出文件与日志仅保存在被忽略的 `output/` 中。

历史本地验证曾用 10 个无密码测试账号累计完成 50 轮真实问答，形成 20 个会话，并核对用户正文、assistant 结构化消息及 JSON/JSONL 导出。该验证使用当时的权限规则；当前所有导出均限超级管理员。旧报告不能作为本次最终版本的发布门禁或真实账务准确性证据。回答内容存在抽查发现的知识错误，保存完整不代表答案正确。

`scripts/test-agent-conversations-live.mjs` 保留手动重现入口，需要自行提供兼容的知识库和模型配置；仅显式设置 `RIIC_LIVE_AGENT_TEST=1` 后才发送 50 轮真实问答，会消耗模型 Token。指定 `RIIC_LIVE_VERIFY_OUTPUT` 可只校验已有本地证据，不再调用模型。此脚本不属于默认测试流程，原始问答及导出数据不进入代码仓库。

原型未实现生产留存期限、累计积分发放预算、敏感操作重新认证、跨设备续聊或历史导入。自动化测试不证明生产容量、远端部署、支付或供应商账单正确；最终版本的验证范围与环境差异应在对应 PR 中记录。
