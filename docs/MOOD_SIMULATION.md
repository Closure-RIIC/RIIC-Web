# 手动排班心情模拟

计算在浏览器 Web Worker 内进行，不调用求解器或新增服务端 API。模拟读取当前手动排班、基建布局和干员练度；全员以 24 心情开始，跨班次和周期继承心情。每班开始重建排班位置，再先处理菲亚梅塔事件、后处理闲置入宿。

顺序轮换和自定义时间区间均支持 24、36、48 小时周期，按草稿中每班的实际时长连续计算。回收站进驻上限按设施等级为 1、2、2 人。基础心情消耗为 1 点/小时，适用的中枢减免和干员技能按其作用范围生效。涣散干员仍占原工位，退出中枢全局减免和制造、贸易的设施减免人数计数。模拟假定设施在班次内持续运转。

## 上游与规则维护

本功能经仓库使用者确认拥有复用授权后，移植自 [Rhodes-MoodSOC](https://github.com/ziyanQAQ/Rhodes-MoodSOC/tree/5204c840b7a99fdf79cd3815507894b001132162)，固定提交为 `5204c840b7a99fdf79cd3815507894b001132162`。技能消耗与恢复计算沿用该模型的技能叠加约定。入宿、床位锁定和菲亚梅塔互换按下方规则执行。

- `apps/arknights/src/mood-simulation/catalog.json`：上游技能子句、解锁和替换、阵营与变量规则的确定性导出。
- `rules.ts`：技能条件、变量、消耗/恢复账本。使用独立 Decimal 上下文（28 位、ROUND_HALF_UP）。
- `engine.ts`：跨班次积分、心情事件、入宿与布局快照；`presentation.ts` 使用事件右侧值查询时间点。
- `catalog-additions.ts`：独立维护固定上游版本未包含的新干员规则，当前补充克莱门莎、德·托莱多、旅骨。依据游戏数据的技能说明、解锁条件及 buffChar 分组核对；重新生成固定目录不会覆盖补充规则。
- 未覆盖且已排班的干员会明确报错；不会默认认为未知干员没有技能。BOX 中未排班且规则尚未覆盖的干员不参与模拟，不再阻断已有排班。新增已排班干员仍需同步并验证规则目录。

开发时可用 Python 重新生成数据及对照样例；生产环境不需要 Python：

```text
python scripts/generate-mood-data.py /path/to/pinned/Rhodes-MoodSOC
python scripts/generate-mood-fixtures.py /path/to/pinned/Rhodes-MoodSOC
npm run test:mood-simulation
```

对照包含 3,131 组独立/组合速率案例和 18 组 1/3/7 周期轨迹，绝对误差小于 1e-6。速率对照扣除工作状态修正带来的差值，轨迹对照验证首次涣散影响减免前的事件和插值。跨天换班、涣散后的速率变化和回收站技能有独立用例。Python 对照数据保留在测试文件中。事件计算保留上游按班次首次出现的干员顺序，以匹配 Decimal 最后精度位上的阈值先后关系。

## 配置边界

菲亚梅塔总开关及每班指定目标与排班共用。指定干员模式下，有目标的班次默认开启，留空时关闭，手动关闭的班次仍保留该设置。自动选人模式需要开启本班开关。启用后，她在任意位置达到 24 心情时每班互换一次，互换只改变心情数值。逐班启停、目标模式和闲置入宿开关保存在本地 `riic.manual-mood.v1`。开始时间只影响时刻标签。

每班按布局顺序从上到下处理宿舍，每间从左到右填床。候选为心情未满的闲置干员，菲亚梅塔优先，其余按入宿时的心情从低到高排列。所有床位按同一规则处理，仅填入未锁定的空床。床位右上角的锁标识仅在排班编辑中可操作，回放中只显示锁定状态。从锁定当班起，锁定的干员或空位在后续班次和循环生效。锁定期间单独保存原排班，解锁后恢复被锁暂时覆盖的安排。床位锁定随本地草稿和可编辑作业图保存，MAA 和 Mower 导出传递对应班次生效的安排。

宿舍氛围默认等级上限；导入干员缺失练度时使用原模型默认精二、等级 30 并显示说明。已有干员练度优先，包括从闲置状态进入宿舍的干员。

## 编辑班次与回放位置

排班草稿由 `ManualSchedulePage` 管理；心情轨迹始终从第一周期第一班连续计算。`mood-simulation/playback.ts` 管理回放定位、播放状态和计算版本，选中干员及其心情明细继续由回放面板管理。播放时钟沿用 `MoodPlaybackStore` 的独立订阅，导航和重算时读取实时游标，不因每次时钟推进重绘整个面板。

- 首次进入回放、在编辑或作业图中选择其他班次，定位到第一周期对应班次起点。再次进入回放时，只有旧位置属于当前编辑班次且尚未到轨迹终点，才保留原周期和进度；否则重新对齐。
- 排班内容、布局或干员练度变化后暂停并重算，使用最新的编辑班次及新结果中的班次起点。计算期间继续切班不重启计算，结果完成后采用最后一次选择；删除班次后采用草稿已校正的有效班次。
- 仅修改模拟设置时暂停并重算，保留观察时间点；缩短周期时将时间限制到新轨迹范围。连续修改期间仍保留尚未完成的班次定位意图。
- 鼠标播放与时间轴空格键使用相同规则；编辑模式开始播放先对齐班次，回放内继续播放沿用当前位置，播放到末尾后再次播放从全轨迹起点开始。拖动、方向键和“回到起点”直接使用用户指定时间，不再被自动对齐覆盖。离开回放暂停，计算完成不会自动切换视图或开始播放。
- 切班、修改开始时刻或切换视图不触发模拟重算。回放期间不把回放班次和模拟安排写回草稿。班次边界沿用事件右侧值，显示新班次及当时已处理事件后的心情。
- 看板与上方“当前班次”的菲亚梅塔、无人机安排由同一次回放渲染提供班次。回放内支援信息只读；重算或失败期间不显示旧的班次支援信息，失败时显示错误并禁用播放和时间轴。

回归覆盖班次 2/3 的切入、同班续看、跨班返回、编辑/作业图改动、模拟设置重算、班次/周期缩减、计算期间切班、过期结果和错误、键盘控制及跨班心情继承。发布前仍须按项目的发布检验规则执行适用门禁。

## 待用户手动验收

- [ ] 打开 /manual，仅看到一套基建看板；切换「排班编辑 / 心情回放」，检查中英文、明暗主题和手机布局。
- [ ] 确认看板上方没有模拟标题、图标和副标题；周期数与播放控件在看板下方。下拉框使用共享 Combobox，列表、明细与设置弹窗使用全站滚动条，心情折线沿用 admin 的图表组件与样式。
- [ ] 编辑模式点击岗位仍能换人、排序、清空和设置自动补位；回放模式点击干员只切换曲线。开始播放或拖动时间轴自动进入回放，切回编辑会暂停且保留原排班。
- [ ] 将周期数改为 3 或 7，播放、暂停、拖动时间轴、回到起点；总长同步变化，跨周期心情连续。
- [ ] 点击模拟看板或干员列表，查看对应曲线、位置、当前心情和消耗/恢复明细。
- [ ] 修改菲亚梅塔指定目标，确认上方对应班次同步。逐班启停和自动选目标仅影响模拟。
- [ ] 模拟设置中的 Switch 可通过标签和键盘切换；闲置入宿使用 Accordion 展开，执行全选/全不选后重算仍保持展开。
- [ ] 桌面端「模拟设置」位于「配置 Box 与布局」右侧，弹窗最大宽度 960px；手机端从更多工具打开且不超出屏幕。草稿与 Box 信息保持单行，两种模式下均无额外操作提示。
- [ ] 查看后续班次的闲置入宿候选；关闭总开关或逐人参与，观察入住变化和事件说明。
- [ ] 模拟前后比较排班和 MAA/Mower 导出，确认仅显式修改的公共菲亚梅塔设置写入排班。
- [ ] 修改排班后立即操作其他配置，确认过期计算不会覆盖新结果；刷新后设置恢复。

受影响 UI：手动排班页面的编辑与回放共用一套看板；共享排班组件通过可选模拟展示参数显示实时心情和选中干员。
