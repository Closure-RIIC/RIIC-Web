# 终末地双应用实施计划

## 已确认的决定

- 一个仓库、npm workspaces、两个独立 TanStack Start 应用和构建产物；不使用单构建 Vite MPA。
- 方舟现有域名和业务保持不变，终末地正式目标域名为 `https://endfield.riic.autos`。游戏切换采用整页导航，不混用两棵路由树。
- 沿用本站 React、TypeScript、Vite、TanStack Start、Base UI、Tailwind 技术栈。
- 共用侧边栏基础组件、外框、滚动行为、账号视觉；终末地右侧使用独立的 `endfield-ui` 组件和主题。
- 不移植 arr-dijiang 的 UI、技术栈或算法。算法及数据使用本站的 [Arr_Solver](https://github.com/ziyanQAQ/Arr_Solver)，固定版本 `455d7f17e06d7bb08ab7cef0f154b72b72455fd4`。
- 本次只在本地开发和验证；不推送、不部署、不改 DNS、不操作线上数据。

## 目录与依赖边界

```text
apps/arknights/              方舟 Start 应用、路由、资源与独立 Vite 配置
apps/endfield/               终末地 Start 应用、路由、独立 Vite 配置
packages/shell/              共享外框样式、游戏选择与侧边栏样式
packages/ui-primitives/      本站现有交互基础组件，不依赖游戏路由
packages/platform/           共同政策版本、森空岛登录与二维码轮询契约
packages/endfield-ui/        终末地内容组件、主题
packages/endfield-solver/    固定版本求解器、适配契约、纯逻辑回归
packages/endfield-skland/    终末地角色、干员与设施数据校验（两应用共用）
```

两站已平级迁移。根目录保留脚本编排、数据库迁移及本地环境文件；方舟的源码、静态资源、翻译和构建入口均位于 `apps/arknights`。资源同步、CI、Worker、standalone 打包与检查同步使用新路径，详见 [双应用工作区](./WORKSPACES.md)。

依赖方向：应用 → shell / UI / solver；共享包不导入应用 routeTree、方舟 App 或游戏 provider。数据库迁移仍只有根目录的一套。

## 实施顺序与验收

1. **共享基础与第二应用**
   - 提取现有侧边栏 primitives 和外框 CSS，方舟以兼容导出继续使用。
   - 新应用独立 routeTree、dist、.output、开发端口（5176）。
   - 游戏选择同时适配展开、收起、手机抽屉；方舟不加载终末地算法或主题。
   - 验收：两应用独立类型检查和构建；5175 ↔ 5176 导航、404、刷新正常。
2. **干员与配置**
   - 固定版本真实干员/技能数据；空名单开始，手动选择、精英化、JSON 导入导出。
   - 设施等级、制造类型、培养槽、类别优先级、中枢助力和搜索预算。
   - 草稿以游戏与版本命名，恢复必须校验；不覆盖方舟数据。
3. **真实排班闭环**
   - 适配 Arr_Solver 的配置、名单、搜索状态、方案和 verifier。
   - 求解放入独立 Worker，取消直接终止 Worker，避免阻塞界面及跨次缓存污染。
   - 展示中枢、舱室两班人员、时刻、产出、心情闭环、缺口与近似说明；不得宣称全局最优。
   - 验收：合法输入、错误输入、取消、重复求解、预算耗尽、对照上游结果。
4. **手动方案与模拟**
   - 基于同一 evaluator 评估手动名单与换班时间；校验人员冲突/容量。
   - UI 明确区分自动搜索、手动评估、稳定闭环、衰减模拟。
5. **账号与后续服务**
   - 复用本站账号，不新增账号库；两站各自提供 `/settings` 和独立 UI，终末地账号菜单提供退出登录。
   - 本地通过现有 5175 会话接口验证身份。正式共享会话需要独立配置跨子域 cookie、trusted origins，发布时另行验收。
   - 森空岛支持终末地专用扫码、凭证登录，或复用方舟已连接账号；先选择终末地角色和服务器，再预览导入名单，可选应用设施等级。云端独立 workspace、抽卡分析、练度建议另行接入；不得使用方舟数据冒充终末地数据。

### 游戏切换时的账号连续性

- 两应用在每次文档请求中读取并校验会话，只把昵称、邮箱、用户 ID 和过期时间交给首屏；不序列化 token、会话 ID 或权限。
- 首屏已有结果时不再重复请求 `/api/auth/get-session`；查询不可用时允许客户端重试。账号状态保存在当前 Provider 内，不在进程或模块中共享账号缓存。
- 返回标签页、恢复浏览器历史页面时重新校验，校验期间保留已有头像和昵称；退出、会话失效和换号以最新响应为准。方舟保留会话 Cookie 续期，终末地桥接禁止独立续期。
- HTML / bootstrap 使用 `private, no-store`。这减少账号二次加载，不能消除不同 origin 之间的整页导航；正式跨子域共享登录仍需独立部署配置。
- `node scripts/test-game-session-e2e.mjs` 使用独立浏览器上下文及模拟会话，覆盖首屏无重复请求、刷新时账号展示、乱序响应、退出、刷新与双向导航；真实登录账号由用户手动验收。

### 两站独立设置与共用账号

- 两站齿轮都进入本站 `/settings`，使用各自的 UI；没有跨站跳转或设置 iframe。通用的主题、语言、图片加载、账号会话续期、退出所有设备、注销账号和本地缓存操作都有入口；游戏专属排班、云端 workspace 等留在对应游戏。
- 显示偏好各站独立保存。终末地语言使用 `riic-endfield-locale` Cookie，首次从旧语言迁移，避免本地端口共用 Cookie 时覆盖方舟语言；主题和图片偏好使用本站 localStorage。
- 终末地设置直接导出、修复和清除本站数据；清除前暂停自动保存并取消求解，避免卸载时写回已删除的名单。账号注销明确作用于两站共用账号，本地清理只影响终末地。
- 终末地使用同一账号 Provider 展示侧栏和设置，复用首屏会话；固定代理只允许当前账号续期、撤销会话、密码确认注销和退出，不接收任意目标、用户 ID 或回调 URL。保留同源 POST、请求体大小、Cookie 过滤和上游账号安全校验。
- `node scripts/test-endfield-settings-e2e.mjs`、`node scripts/test-game-session-e2e.mjs` 使用隔离数据验证双站入口、显示偏好隔离、数据导出/清理、账号操作成功/失败、注销确认和退出乱序；不操作真实账号。

### 终末地背景与顶部区域

- 移除重复的顶部站点标识；手机端保留独立侧边栏展开按钮。
- 右侧浅色背景为白色，使用 45–80px 网格及 5px 间距斜纹（相对最初版本线性密度约 4 倍），整层纹理从底部向上淡出。深色模式沿用深色底色；纹理不需要图片请求或动画。
- 外框高度及内部滚动保持原有结构；手动验收覆盖桌面浅色、深色和手机菜单。
- 水平与垂直格线按容器尺寸完整平铺，不再叠加对角切格；各页面标题统一为方舟的标题格式，移除英文装饰标语。

### 终末地森空岛同步

- 首次登录沿用方舟的扫码 / 凭证双选项；登录后自动进入数据总览，后续通过“添加账号”弹窗登录。支持 5 个独立终末地账号及旧 Cookie，移除森空岛 JSON 导入入口。
- 终末地服务只代理固定森空岛接口到配置的本站账号服务；沿用网站登录、同源校验、限流、加密 Cookie 与账号归属。终末地扫码会话、Cookie 独立，不改变方舟当前角色。
- 同步前验证角色与服务器归属；按干员 ID 及终末地唯一精确名称对照自有求解器。干员不完整时保留数据展示但禁用名单导入。数据按角色、干员装备、帝江号、地区探索和其他资料分类，排除凭据；嵌套详情按需展开。设施等级默认不覆盖，需用户勾选。
- 本地自动化使用模拟 API 和独立浏览器上下文，不读取真实用户凭据、不写线上数据库。正式域名的 Cookie/账号桥接仍须单独配置。
