# 两站国际化维护

运行时继续使用 `use-intl`；x18n 只参与开发、编辑器和检查流程。默认 `zh-CN`，另支持台湾繁体 `zh-TW` 和英文 `en`，不根据浏览器语言自动选择。

## 资源归属

| 内容 | 权威来源 |
| --- | --- |
| 语言、别名、cookie 和跨站参数 | `packages/contracts/locale.ts` |
| 两站界面 | `apps/{arknights,endfield}/messages/{zh-CN,zh-TW,en}` |
| 共享账号、侧边栏、控件 | `packages/shell/messages/{zh-CN,zh-TW,en}` |
| 方舟领域展示文案 | `packages/arknights-domain/messages/{zh-CN,zh-TW,en}` |
| 方舟游戏文字（生成） | `apps/arknights/src/generated/i18n` |
| 终末地游戏文字（生成） | `packages/endfield-data/messages` |

旧文件映射见 `i18n-migration-map.json`。不要恢复双语静态聚合导入。每个 namespace 只有一个权威来源；共享资源由两站 x18n 项目共同引用。

React 界面使用 `useTranslations`；纯展示函数使用 `createLocalizer`，显式传入 locale。调用边界先加载所需 namespace；独立服务端工具不能依赖其他请求碰巧加载过资源。禁止添加全局“当前语言”。

`src/i18n/messages.ts`、`loaders/{locale}.ts` 和 `feature-manifest.ts` 由生成器维护。根、路由、弹窗分别加载所需资源。新增懒加载弹窗复用 `lazyWithMessages`；路由 HOC 放在顶层具名常量中以兼容路由拆包。

方舟简体的游戏展示直接使用业务模块已有的规范资料，加载器只提供空的翻译覆盖表，避免 SSR 重复传输完整中文游戏词典；完整生成文件仍用于来源、覆盖率和 hash 校验。繁体和英文加载各自的翻译覆盖表，新增消费方需保留规范资料回退。

两站动态 HTML 使用 `@riic/platform-server/html-compression` 流式 gzip，避免新增 SSR 词条按原始体积传输。入口先执行原有权限和缓存规则，再调用压缩工具；保持私有响应头、Cookie 和 `Vary`，跳过非 HTML 与已压缩响应。相关非 UI 回归包含在 `npm run test:platform` 中。

## 修改流程

1. 同时修改三语 JSON。使用稳定键和完整 ICU 句子；数字、用户输入、URL 和 JSX 插槽通过参数传入，不拼接翻译片段。
2. 运行 `npm run i18n:generate`，然后运行 `npm run check:i18n`。生成器的 `--check` 阻止遗漏派生产物。
3. `npm run i18n:status` 查看覆盖，`npm run i18n:ui` 打开本地词条编辑器。工作区推荐扩展为 `antfu.x18n-vscode`。
4. 机器报告使用 `npm run i18n:check -- --reporter json --output .tmp/x18n-report.json`；CI 注释可使用 `--reporter github`。

缺 key、缺译、空译文、ICU 语法/参数/富文本标签错误和键冲突会阻断。自定义扫描器识别显式 locale helper、有限映射、结构化 records 和部分来源契约。新增动态调用应提供有限键映射并补纯解析 fixture，不能把未知调用当作整个 namespace 都已使用。清理 unused/stale 前核对间接消费者。

x18n 0.1.2 按源码范围去重引用。为保留同一动态调用解析出的多个键，`generate-i18n-usages.mjs` 从源码生成 `apps/*/i18n/usage-manifest.ts`，每个引用有独立范围和来源行号；它不从词典反推引用，也不进入生产依赖图。扫描器按词法作用域识别翻译函数、ref 和有类型的函数参数。已清理词条记录在 `i18n-removed-keys.json`。

禁止在模块顶层调用翻译函数：懒加载模块求值时，其资源可能尚未到达。`lazy-initialization.test.mjs` 检查这一边界；组件或纯展示函数在所属 feature 加载完成后才读取文案。

## 语言与状态

有效 `ui_locale` 优先于本站 cookie；随后为客户端一次性旧偏好迁移和简体默认值。跨站链接携带白名单语言参数，SSR 消费后只移除该参数，保留其他查询和 hash。两站分别使用 `riic-locale`、`riic-endfield-locale`。

切换先加载当前所有已请求的 namespace，成功后一起更新快照和 cookie。失败保留现有语言并允许重试，早发请求不能覆盖后发选择。组件不能用 locale 作 key；请求、存档恢复与保存不应依赖翻译函数身份，错误码在显示时翻译。

以下内容不自动改写：

- 用户标题、许愿、聊天、技能注释、账号名称和数据库历史公告。新公告支持 `tw`，旧公告无 `tw` 时保留原文。
- 求解器、MAA、Mower、存档及导入导出的规范名称。批量排班文字协议继续使用原有简体名称，界面说明和错误使用当前语言。
- Agent 工具内部上下文、固定协议、请求编号、错误码、原始技术诊断、备案编号。
- `building-rooms.ts`、`schedule.ts`、`daily-production-presentation.ts` 等文件中用于匹配的规范值；消费界面负责本地化，不能直接显示这些值。
- 受管游戏数据、测试及不可变历史迁移 fixture；演示 fixture 不直接成为生产界面文案。

## 游戏资料

方舟：`node scripts/sync-arknights-i18n-data.mjs`。终末地：`node scripts/sync-endfield-display-data.mjs --text-only`。首次下载固定提交，`--offline` 复用本地源缓存，`--check` 核对产物。方舟还校验规范输入和人工覆盖 hash。

方舟人工审校位于 `apps/arknights/i18n/game-overrides/{en,zh-TW}.json`。生成目录 `sources.json.coverage` 记录地区缺口：`manual` 为本站审校译文，`legacy-english` 为已有英文资料，两者不自动等同官方译名。终末地使用 CN/EN/TC 表，无损解析 64 位文字 ID。不要用普通 JSON Number 读取这些 ID。

搜索别名关联稳定 ID / 规范名称，不更改选择或求解输入。受管游戏词典不放入 x18n 可写资源。人工技能译文保留数值和富文本标记。

## 验证与发布

检查包括 `check:i18n`、`check:types`、`lint`、`test:workspace`、相关纯逻辑测试、两站生产构建及原有包体积检查。`scripts/test-i18n-e2e.mjs` 只允许本地服务，使用隔离浏览器与模拟账号数据；人工 UI 验收另行记录。

`scripts/test-i18n-state-e2e.mjs` 覆盖排班草稿、Mower 导出、任务轮询、终末地名单、延迟资源和并发 SSR。管理员部分使用 `node scripts/start-admin-preview.mjs 5199` 提供的开发专用内存 fixture。`I18N_ADMIN_ONLY=1` 可单独执行管理员部分，`I18N_SKIP_ADMIN=1` 可执行其余部分；交付时需分别记录结果，不能以跳过作为通过。

`node scripts/measure-i18n.mjs` 使用本地生产服务比较相同基线与候选配置。默认端口为候选 5195/5196、基线 5197/5198；样本写入 `.tmp/i18n-performance.json`。测试资源使用新浏览器上下文，不访问真实账号。服务端 HTML 的内联 bootstrap 大小是序列化数据的代理指标，不能报告成精确消息 JSON 大小。

采样可用 `I18N_PERF_APP`、`I18N_PERF_LOCALE`、`I18N_PERF_MOBILE`、`I18N_PERF_ROUTE` 限定场景，以 `I18N_PERF_OUTPUT` 指定结果文件。`I18N_PERF_RESUME=1` 只复用完整的单次场景；仅在生产产物、配置及测量方法相同的情况下续跑，修改实现后使用新输出文件重测受影响场景。计时期间避免构建、其他测试及系统休眠。账号计时从选择登录开始；方舟干员计时包含打开设置并选择手动名单的流程。

不把 x18n/OpenCC 放进生产运行链路，不提高包体积门槛。性能结果记录环境、缓存、至少 10 次采样的中位数/p95；不把库宣传值或单次加载当作本站收益。

本批不涉及生产数据迁移。发布时代码和资源使用同一版本，通过现有分支与环境门禁；保持旧 cookie 和存档兼容。本地实施及性能证据见 [实施记录](I18N_IMPLEMENTATION_REPORT.md) 和 [性能记录](I18N_PERFORMANCE.md)，CI 与各环境部署状态单独核对。
