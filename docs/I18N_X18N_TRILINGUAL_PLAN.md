**RIIC-Web 两站 x18n 接入与三语国际化计划**

状态：待实施。本文仅规划，不安装依赖、不改业务实现、不触发 CI 或发布。

规划日期：2026-10-29。代码核对基线：已发布 main `3945dfb62f976f8d64ea27d1aaca4cd7fb144079`，对应 develop 代码树相同。实施时从最新目标分支重新核对差异。

用户已确认：两站完整接入；默认简体中文；新增台湾繁体中文 `zh-TW`，保留并完善英文。

**1. 技术选型与结论**

推荐采用 **x18n 管理和检查词条 + use-intl 统一运行时 + 按语言、功能模块加载资源**。两站和共享组件使用同一套语言契约，各自拥有自己的翻译资源。x18n 仅作为开发依赖，不进入生产页面运行链路。

x18n 的官方文档提供多个框架预设，没有给出适用于本站的性能排名。接入 x18n 与更换运行时是两个独立决策。

| 方案 | 性能机制 | 本站适配与代价 | 本计划决定 |
| --- | --- | --- | --- |
| use-intl | 通过显式传入 messages 控制加载范围；应用负责语言和模块拆分 | 已支持现有 ICU、富文本、SSR、非 React 翻译函数；迁移成本最低 | 作为正式实现主方案，消除现有整包加载与双语言静态导入 |
| Paraglide JS | 编译为可被 tree-shaking 的消息函数，有 TanStack Start 官方集成示例 | 默认保留已使用消息的多种语言；默认切换使用整页导航；实验性按语言构建目前不能直接用于 TanStack Start；现有动态键、富文本和结构化记录需验证 | 作为阶段 0 的限定性能对照，不直接全站替换 |
| Lingui | 消息预编译、生产移除默认文案、按语言动态加载 catalog | 能减少运行期解析和重复文案，但需要替换调用方式、配置编译链、处理 SSR 实例隔离及现有 ICU/富文本兼容 | 记录为后续候选，本轮不同时维护第三套运行时 |

关于 Paraglide 的结论是基于其当前文档的适用范围判断，不代表它在本站已实测更慢。不能把其他项目宣传的体积降幅写成本站收益。use-intl 在 TanStack Start 中也不自动拥有 Next.js 专用的服务端组件优化或插件能力。

阶段 0 用同一组真实页面、相同词条及三种语言，对比当前实现、拆分后的 use-intl 和一个隔离的 Paraglide 样例。默认按 use-intl 主方案继续；只有替代方案满足全部状态/SSR/富文本验收，而且关键入口冷加载总传输量相对拆分后的 use-intl 同时减少至少 10% 和 10 KiB，才提出单独的运行时迁移决策。该阈值是本计划采用的决策门槛，不是现有测量结果。未获得有代表性的收益就结束换库探索，不拖延三语接入。

**2. 当前实现及需要处理的范围**

| 位置 | 已核实的情况 | 实施重点 |
| --- | --- | --- |
| `apps/arknights/src/i18n/locale.ts`、`routes/__root.tsx` | 根 loader 加载当前语言完整 messages，再传给根 Provider | 根仅保留基础界面与 Metadata，其余按路由/功能加载，减少首屏序列化 |
| `apps/arknights/messages`、`packages/arknights-domain/messages` | 约 40 个中文 JSON 文件、2,418 个字符串叶子，含结构化展示记录 | 保留稳定键、参数和结构，补全三语；统计不代表互不重复的翻译词条 |
| `createLocalizer` 与各 helper | 在模块顶部导入中英文并创建双语 translator | 改为显式 locale 和已加载资源，避免扩展成三份同时进入初始依赖图 |
| `apps/endfield/src/state.tsx`、`routes/__root.tsx` | 以 `t(zh, en)` 选择文案，初始状态和 SSR 文档固定简体，挂载后读取 cookie | 将语言从排班状态中分离，SSR 解析语言并与 hydration 一致 |
| 终末地 TS/TSX | 静态 AST 统计 36 个文件、615 处双参数 `t()` 调用，其中 27 处含模板插值 | 逐模块提取；另扫描条件表达式、常量、标题、可访问名称等，不把该统计当完整清单 |
| `packages/shell/auth` | 135 个中文字符串叶子；其他共享组件也有内联中英文 | 账号、导航、游戏切换、语言菜单使用共享三语资源 |
| 语言开关与设置 | 类型多处限制为 `zh/en`；方舟的英文选择与 `loadEnglishResources` 耦合 | 改为三语契约，界面语种选择和游戏资料预加载分开 |
| 游戏展示数据 | 方舟有英文名称/技能生成数据；终末地同步脚本仅读取 CN/EN 表 | 扩展生成与来源记录，不能直接编辑生成结果 |
| `scripts/check-i18n.mjs` | 已检查两语键集合、ICU 可执行性和部分结构化记录 | 扩展到三语、两站和共享资源，与 x18n 检查互补 |

完整范围包括两站全部站内界面：导航、语言菜单、设置、账号弹窗、排班配置和报告、手动排班、技能查询、工具提示、对话框、通知、错误/空状态、管理页面、站内帮助、静态说明、更新日志、页面标题和描述、404、无脚本提示，以及图片导出中的界面文案。保持已有权限边界。

用户输入、第三方原文、账号标识、调试日志、数据库内容不做自动改写。游戏数据是单独的本地化数据流；有源数据时优先采用，缺少官方对应语言时提供审校译文或记录明确的原文回退，不把简繁转换标为官方译名。

**3. 三语契约与语言选择行为**

| 语言 | 内部规范值及 HTML lang | 菜单显示 |
| --- | --- | --- |
| 简体中文 | `zh-CN` | 简体中文 |
| 台湾繁体中文 | `zh-TW` | 繁體中文（台灣） |
| 英文 | `en` | English |

在 `packages/contracts/locale.ts` 增加纯数据契约与规范化函数，通过包的显式 exports 引用。集中定义 `AppLocale`、支持语种、默认值和兼容别名；不在该文件引入 React、文件读取或请求全局状态。

- 无显式偏好一律使用 `zh-CN`，不因浏览器语言或地区自动改为英文/繁体。明确检查并约束旧 `PUBLIC_DEFAULT_LOCALE` 配置，使默认简体不受旧环境值意外覆盖。
- 兼容旧 `zh`、`zh-Hans`、`zh-CN` 为简体，`zh-TW`、`zh-Hant` 为台湾繁体，`en`、`en-US`、`en-GB` 为英文；其他值回默认值。若接收 `zh-HK`，明确按本站唯一繁体版本 `zh-TW` 兼容，不宣称提供香港用词。
- 保留现有两站 cookie 名称，读取时规范化，下一次明确选择时写规范值。旧 localStorage 偏好的迁移保留为一次性兼容步骤；浏览器存储不可用时仍可使用默认界面。
- 解析优先级为：经过白名单校验的显式切换参数、本站语言 cookie、已有的兼容偏好、默认简体。旧 localStorage 只能在客户端做一次性迁移，不能假装服务端能读取它。
- 两站继续各自记忆偏好。顶部游戏切换器携带一次性的 `ui_locale`，目标站在 SSR 时消费、写本站 cookie，移除该参数并保留其余 URL 状态。限制为支持语种，不扩大 cookie Domain，不涉及登录凭据。
- 沿用现有页面路径，不给所有路由添加语言前缀；本轮不生成没有独立可访问目标的 hreflang。HTML lang、Metadata、格式化语言与页面内容一致。
- 匿名用户和登录用户均能在桌面与手机切换三种语言。语言菜单不能被账号登录状态或“关闭英文资源”设置锁住。
- 将旧英文资源设置迁移为游戏翻译资料的预加载偏好；选择某个语言时按需获取必要资料，关闭预加载不再禁止使用英文界面。
- 切换时保留当前路由、查询条件、排班草稿、选中干员、编辑中的表单、正在进行的任务和可恢复的弹窗状态。资源成功到达后一次性切换；失败时保持原语言并提供重试，避免半页新语言半页旧语言。

移除三语路径中的 `isEnglish`/布尔语言参数和“非英文即简体”的判断，使用显式 locale 分支与穷尽类型检查。日期、数字和复数按语言格式化；排班计算、业务时间和已有时区约定不因切换语言改变。

**4. 消息目录与加载设计**

目标目录采用相同约定，每个目录的三种语言分别具有一致的命名空间：

```text
x18n.config.ts
apps/arknights/messages/{locale}/{namespace}.json
apps/endfield/messages/{locale}/{namespace}.json
packages/shell/messages/{locale}/{namespace}.json
packages/arknights-domain/messages/{locale}/{namespace}.json
packages/endfield-ui/messages/{locale}/{namespace}.json  # 仅放该包自行渲染的文案
packages/contracts/locale.ts
```

最终资源归属按文案的实际拥有者确定。只被应用使用的文案不为“共享”而搬到公共包；公共包不能导入应用资源。迁移现有文件时建立旧路径/旧键到新位置的对应表，不把所有词条顺手重命名。

- 简体为 source locale。新增键使用稳定、有上下文的语义名，例如 `roster.upgrade.ownedCount`，不以完整中文或文件路径充当新键。
- 同一个 namespace 的 message ID、ICU 参数和富文本标签契约在三语中一致。显示相同但语义不同的短语可以保留不同键。
- 将数量、剩余时间、范围等改成完整 ICU 消息；英文使用 plural，避免 `1 operators` 或把一句话拆成多个翻译片段。
- 结构化展示数组保留稳定 ID、顺序和非文案数据；其文案引用消息键，或用明确的结构化资源适配器检查。运行时动态索引必须可枚举，不通过整片忽略检查来消除误报。
- 普通文本、富文本、纯逻辑格式化各使用现有 use-intl 能力；不会创建一层无必要的“兼容所有 i18n 框架”抽象。
- 根资源只包含导航、基础控件、公共错误和 Metadata。排班、技能、设置、管理页、帮助、游戏字典、账号弹窗按需加载。
- 每个加载入口显式按 locale 导入资源；避免聚合模块静态导入所有语言。按 `(locale, namespace, buildVersion)` 缓存不可变资源，在切换时复用已加载结果。
- 两站 SSR 各自解析请求语言并提供当前页所需词条。纯资源模块可缓存，当前用户语言和有账号信息的请求上下文不能跨请求共享。
- 保留方舟现有 Provider 隔离和手动排班草稿恢复相关约束。调整 Provider 层次和 messages 对象身份时覆盖既有的 combobox 更新循环回归。
- 服务端与客户端采用同一份语言快照；不靠 hydration warning suppression 掩盖语言不一致。新增动态路由查询参数通过既有路由类型生成流程更新。

**5. x18n 接入与维护方式**

根目录固定版本安装 `@x18n/cli` 开发依赖，使用现有根锁文件；不装进每个应用的生产依赖。以 `sourceLocale: 'zh-CN'` 和三语白名单配置项目。

root 配置管理两站和实际持有消息的共享包，各子项目显式配置 resources、usage 和 namespace。共享词条只有一个权威源；跨应用引用通过可解释的扫描配置或小型适配器关联，避免复制共享词典来“凑齐”应用检查。

- 标准 `useTranslations` 使用 x18n 的 next-intl 预设。
- 为迁移期间的 `localize.text(locale, key)`、`localize.rich(locale, key, values)` 配置第二个参数为 key，并准确关联 helper 对应的 namespace；为结构化 records、错误码映射提供明确引用规则。
- 用纯解析 fixture 验证自定义扫描器能识别真实使用、非法 key 和 namespace；这些是非 UI 测试。
- 生成数据、上游源码和机器日志排除在可写资源外。游戏术语表作为校验输入；x18n 不改写生成文件。
- 提供 `i18n:status`、`i18n:check`、`i18n:ui` 和可供 CI 使用的 JSON/GitHub reporter。保留 `check:i18n` 作为统一入口，覆盖已有 ICU/结构检查与新增 x18n 检查，避免团队维护两套互相不一致的命令。
- 缺 key、缺翻译、ICU 错误、参数/富文本标签不一致、重复冲突和资源解析失败进入阻断项。空字符串有确切用途时按键记录理由，不使用全局关闭规则。
- unused、stale、术语与硬编码检查先校准现有基线；对新增/修改内容立即执行规则，完成迁移后清空未处置项。全站启用硬编码检查前明确技术常量、游戏 ID、用户文本等合法例外。
- 未使用词条只能在标准调用、自定义 helper、结构化记录和动态映射均扫描后清理。不能依据首次扫描结果直接批量删除。
- VS Code/LSP 和本地 UI 使用同一配置。推荐工作区扩展，不自动改个人编辑器全局设置；MCP 是可选维护入口，不作为构建和发布前提。

**6. 翻译与游戏资料**

建立分域术语表：共享界面术语、明日方舟术语、终末地术语。台湾繁体遵循该游戏的台湾用语和官方译名；同一中文词在不同游戏可能需要不同翻译。

简繁转换工具只在离线准备草稿时使用，保护 ICU 参数、标签、URL、标识符和专有名词；不在浏览器运行时整页转换。对按钮、帮助、错误说明和报告逐项审校，英文同时修正现有拼接、单复数和不一致术语。任何未获会话授权的外部翻译服务不在实现中默认调用。

游戏数据的任务包含：

1. 清点两站现有名称/技能/设施/材料显示入口和搜索索引；以 ID 或现有稳定业务键关联语言，保留存档与求解器使用的原始标识。
2. 在固定的数据版本中核对台湾繁体文本是否存在、实际表名和覆盖范围。终末地当前脚本只枚举 CN/EN，不能假定已有可用 TW 表。
3. 扩展现有同步/生成脚本与来源清单，记录版本、源文件和 hash；人工译名覆盖放在独立人工维护层，不只手改生成 JSON。
4. 将展示字典按语言拆分。界面词条通过 x18n 管理；受管数据使用生成器、覆盖率和引用校验，不当作普通可编辑 UI 词条。
5. 搜索支持当前语言及原始名称别名；切换语言不改变角色选择、技能标识、报告数据、导入导出协议、MAA 名称或云存档身份。
6. 为缺失的地区译名保留有来源的缺口清单、审校译文和显式 fallback；正常功能界面三语覆盖必须达到 100%。技术上能回退不等于翻译完成。

**7. 实施顺序与阶段交付**

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| P0 清单与性能基线 | UI/数据/动态键清单；三语资源来源核查；当前与优化样例的体积、SSR 和交互对照 | 明确运行时主方案、资源归属和例外，记录测量环境，不先展开全站换库 |
| P1 语言基础设施 | 共享语言契约、旧偏好迁移、两站 SSR/客户端语言上下文、三语菜单、完整请求隔离 | 无偏好始终简体；已保存繁体/英文首屏一致；切换不丢状态；不提前公开未覆盖的语种 |
| P2 x18n 与资源迁移 | 配置、helper 扫描规则、三语目录、结构化记录与完整句子改造 | 全部源码入口可追踪；源语言行为保持一致；没有为消除误报而关闭整类检查 |
| P3 三语内容与资料 | 方舟、终末地、共享 UI 全量翻译；游戏显示层和搜索别名；Metadata/帮助/错误页 | 无未处理站内文案缺译；参数、术语和结构校验通过；数据缺口有明确处置 |
| P4 按需加载与性能收尾 | 根/路由/弹窗资源拆分；移除双语言导入；按语言缓存；性能结果与预算检查 | 选中一种语言时不载入整套其他语言；新增繁体不让简体首屏承担完整第三套词条 |
| P5 验证与交付 | 非 UI 测试、Node + Playwright E2E、CI、人工验收清单、使用文档和发布说明 | 两站三语全部满足最终验收，保留既有发布门禁；按后续实施/发布授权推进环境发布 |

各阶段可以形成独立可审查提交；最终交付同时覆盖两站，不以只接编辑器扩展或只迁移几个页面作为完成。三语菜单只在全量内容可用后向用户开放。阶段性的兼容封装在迁移结束时清理，避免长期保留两种文案来源。

**8. 性能验证与门槛**

使用生产构建、本地隔离服务和固定浏览器配置，分别测量两站首页/自动排班、手动排班、技能页、我的干员/账号弹窗；覆盖三语、冷/热缓存和桌面/手机。基线与候选使用同一份词条、相同数据和相同业务操作。

记录入口及异步 chunks 的 gzip/Brotli 字节、实际网络传输、SSR 序列化消息大小、SSR 耗时、hydration/交互就绪耗时、首次及已缓存切换耗时、模块预取情况和 build 时间。小型 `t()` 调用微基准不作为全站性能结论。

验收目标：

- 不引入 x18n CLI/LSP/UI、翻译转换工具或完整其他语言词典到生产初始依赖图。
- 简体入口不请求整套英文/繁体游戏字典，账号/管理/帮助资源按功能触发加载。
- 现有 bundle budget 继续通过，不能提高阈值来掩盖回归。
- 稳定环境至少 10 次采样，报告中位数与 p95；初始传输量不得明显倒退，SSR/hydration/常用交互超过基线 5% 的变化须复测并定位，不对噪声样本宣布优化成果。
- 静态资源因旧构建缓存失配时采用既有恢复机制；语言加载失败保持当前可用语言和状态，不能清空草稿。

**9. 验证、CI 与人工验收**

本地执行范围：`check:i18n`、两站及受影响平台类型检查、ESLint、`test:workspace`、相关纯逻辑测试、两站构建及现有构建产物/包体积检查。依赖与共享契约变化时按影响扩大检查。新增测试仅覆盖非 UI 逻辑和 Node + Playwright E2E；不新增或本地运行 UI 单元测试。CI 保留既有质量门，不为此计划删除测试或放宽保护。

非 UI 回归包括：locale 规范化/无效输入/旧 cookie、结构化 records 键和顺序、ICU 参数与 rich tag、动态调用扫描、数据 ID 与64位文本 ID 保真、生成过程可复现、游戏名称搜索别名、并发 SSR 请求的语种隔离、资源加载失败恢复。

Node + Playwright E2E 的最小矩阵为两站 × 三语 × 桌面/手机 × 匿名/普通用户；管理员页面另外使用隔离管理员 fixture。校验服务端 HTML lang 和首屏文字、无 hydration mismatch、刷新与直接访问、账号弹窗、顶部站点切换、键盘菜单、报告和导出、繁体字符显示、英文长文案、切换前后草稿和任务一致。注入延迟或失败的资源请求覆盖连续切换、失败重试；验证从英文浏览器首次访问仍默认简体。使用隔离测试数据，不修改真实用户存档。

CI 将三语检查接到两站 PR 必需检查与发布前验证入口，覆盖所有受影响共享包；报告包含扫描覆盖、翻译覆盖和例外清单。临时基线有明确消除条件，最终交付不保留未说明的缺译。

受影响 UI：两站全站文案、共享账号与语言选择、游戏切换、排班报告/导出、技能和角色显示、搜索结果、页面标题和异常页面。以下为实施完成后待用户验证的人工 Todo：

- [ ] 两站首次访问（浏览器分别设为英文/繁体）均显示简体；选择台湾繁体/英文后刷新保持选择，标题和页面语言一致。
- [ ] 匿名与登录状态、桌面与手机均能切换三语；顶部切换到另一游戏后保持所选语言，登录状态正常。
- [ ] 编辑手动排班、筛选干员、打开报告/账号弹窗时切换语言，已有输入、干员选择、计算结果和任务状态不丢失。
- [ ] 台湾繁体的游戏术语、按钮、帮助和错误说明符合台湾用语；数字、技能参数、角色对应关系与简体一致。
- [ ] 英文长文案及繁体字形在 320/390px 手机和桌面正常显示，菜单、工具提示、侧边栏和弹窗不遮挡关键操作。
- [ ] 两站报告查看与图片导出使用当前语言；机器可读数据导出、导入、MAA/存档仍兼容原格式。
- [ ] 普通用户看不到管理功能；隔离管理员账号验证管理页三语；断网/加载失败可恢复且不会重置工作区。

**10. 发布与回滚计划**

本轮只交付计划。实施完成后的发布按当次授权和仓库策略执行：先将完整改动通过 PR 合入 develop，完成两站 CI、部署健康检查和三语验收，再从包含已验证 develop 的同仓库 `release/*` 分支向 main 提 PR，完成必需检查与正常生产环境审批。发布前重新核对实际 diff 与每个应用的部署基线。

三语资源与消费它们的代码作为同一个版本发布。资源 URL 带构建版本，避免旧页面取到不兼容的新词典。保持旧 cookie 和存档的兼容读取；不迁移生产数据库，不更改求解器身份。两站共享契约先保持向后兼容，使应用可以分别回滚至上一份已验证产物；新 locale 在旧版本中最多回到默认简体，不使站点失效。分别记录本地验证、CI、环境部署和用户人工验收结果。

最终完成标准：两站站内 UI 的简体/台湾繁体/英文覆盖完整，x18n 的资源和调用覆盖完整，SSR 与客户端语言一致，语言选择不丢业务状态，按语言/模块加载经测量验证，CI 和生产门禁按真实结果通过，数据翻译缺口如实列明，人工验收状态单独记录。
